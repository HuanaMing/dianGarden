# 任務223：修正自動地塊 1 異常被選取

## 類型
Bug 修正

## 問題描述
玩家操作或遊戲更新時，自動地塊 1 會反覆或非預期地被選取，影響農地管理與目前選取狀態。

## 調查範圍
- 檢查自動地塊清單的顯示編號與內部地塊索引是否一致，特別是索引 0／地塊 1。
- 檢查自動／手動地塊分流、選取狀態初始化及切換邏輯。
- 檢查面板重繪、定時更新、存檔載入及遊戲狀態同步時，是否意外重設選取目標。
- 檢查 `game.js` 與 `sky-world.js` 之間選取狀態的傳遞；依實際程式結構調整，不預設問題一定出在特定模組。

## 修改原則
先重現並定位原因，再以最小修改修正；避免只用額外條件掩蓋索引或狀態同步錯誤。不得破壞手工地塊選取、場景點選、農地管理列表或既有存檔相容性。

## 驗收條件
- 不操作時，自動地塊 1 不會被無故反覆選取。
- 點選其他自動地塊後，選取狀態維持正確，不會自行跳回地塊 1。
- 切換自動／手動地塊、重新載入存檔及面板更新後，選取狀態正確。
- 手工地塊與 3D 場景的既有選取行為不受影響。
- 執行可用的相關測試；若無法在真實瀏覽器重現或驗證，需清楚記錄限制。

## 執行紀錄
- 第一輪修正不完整：雖然 `activePlotIndex === -1` 時已保留取消選取狀態，但 `render()` 在已選地塊不屬於目前管理分頁時，仍會改選該分頁第一塊地。3D 場景選取手動農地或草地時，若面板仍在自動分頁，會被自動地塊 1 覆蓋。
- 第二輪程式修正：`selectPlot(index)` 依選中地塊的 `manual` 屬性同步切換自動／手動管理分頁，再重繪地塊清單；草地與手動農地都屬於手動分頁，因此不再被自動分頁的第一塊地覆蓋。保留先前對明確取消選取狀態的修正。
- 回歸測試：`tests/browser-smoke.mjs` 的地塊測試資料加入草地，並新增場景選取草地、手動農地後等待超過一個週期重繪的案例，確認分頁及選取索引仍正確；原有取消選取案例繼續保留。
- 驗證狀態：重新讀取 GitHub 上的 `src/game.js` 與 `tests/browser-smoke.mjs`，確認修改已寫入；`src/game.js` 語法解析通過。測試腳本使用含頂層 `await` 的 ES module 格式，需以模組／async 包裝方式檢查；尚未實際執行 Playwright 瀏覽器測試，不能宣稱瀏覽器驗收通過。
