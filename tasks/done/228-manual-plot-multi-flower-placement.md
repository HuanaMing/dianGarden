# 任務228：手動地塊多株種植資料模型與位置演算法

## 需求
設計並實作同一手動地塊可容納多株花卉的資料模型，以及每株花卉在地塊上的穩定位置決定機制。位置函數要求第一株固定為 `f(1)=(0.5, 0.5)`；第 n 株為 `f(n)=(x,y)`，分布不能過度整齊，要有自然、略帶隨機的感覺，且允許座標超出土壤床範圍。

## 設計原則
- 先確認現有 `plot.crop`、`plantedAt`、成長、澆水、收成、花卉高度及無人機派工等流程，再設計相容的多株資料結構。
- 舊存檔中每塊地原本的一株花必須自動轉換為一株陣列項目，不得丟失花種、種植時間、成長、澆水、變種及高度資訊。
- `f(1)` 固定置中；後續位置使用可重現的偽隨機或穩定種子機制，避免重新整理或重新繪製後位置跳動。
- 位置以土壤床的局部正規化座標表示；不要將座標硬限制在 0 到 1，讓部分花卉可自然越出土壤床邊緣。
- 位置要有最小間距與合理分布，避免重疊成一團或形成明顯方格／同心圓；需定義超出範圍的合理上限，避免花卉飄得過遠。
- 確保遊戲主場景、圖鑑、存檔讀取及舊版資料仍相容。

## 驗收條件
- 空手動地塊第一株的位置等於 `(0.5,0.5))；後續株位穩定且有自然、不規則的視覺分布。
- 同一地塊上的多株能各自保留花種、成長及狀態，不因刷新或重新載入而改變位置。
- 允許部分花株超出土壤床範圍，但不會無限制遠離地塊。
- 舊存檔自動相容，既有單株手動地塊與自動地塊玩法不退化。
- 測試覆蓋位置可重現性、資料遷移與多株渲染。

## 依賴
此任務是任務229（手動地塊升級容量）的技術前置。先完成多株資料模型，再讓升級增加容量，避免只增加 UI 卻無法實際種植多株。


## 執行結果
- 已建立手動地塊多株資料模型；每株各自保存花種、種植時間、高度、變種、澆水狀態與成長加成。
- 舊版單株手動地塊存檔會自動轉換成 `plants` 陣列，並在啟動時立即寫回，避免下次重載再次使用舊格式。
- 第一株固定在局部座標 `(0.5, 0.5)`；後續株位由穩定的偽隨機函數決定，允許有限度超出土壤床。
- 主場景渲染支援多株花卉；手動地塊操作視窗可逐株查看進度、澆水與收成。
- 離線天氣與澆水結算已納入多株狀態；多株地塊的草地切換會檢查各株是否成熟，成熟花株可保留。
