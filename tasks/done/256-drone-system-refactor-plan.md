# 任務256：無人機任務與動畫系統重構規劃

## 狀態
進行中：已獲使用者批准方案 B，正在建立規格、分階段任務及驗收計畫。此任務本身不代表核心程式已重構。

## 需求
使用者觀察到無人機在採收完成後瞬移，以及播種結束後跳至同一地塊較高處開始澆水動畫，希望整體整理任務與動畫系統，而非持續針對單一動畫補丁。使用者批准「分階段重構、逐步替換」方案。

## 主要規格
詳見 `docs/drone-system-refactor.md`。核心分層：
1. 任務管理器：任務建立、派工、重試、取消與結果一次性提交。
2. 無人機狀態機：統一管理待命、前往、工作、返航、充電及等待路徑等階段。
3. 位置與路徑控制器：唯一更新世界座標，負責路徑、工作高度、返航與重規劃。
4. 動畫呈現層：呈現狀態與特效，不自行派工、提交遊戲結果或重設世界座標。

## 主要原則
- 小步提交，逐階段驗收，不一次性重寫。
- 保留原生 HTML/CSS/JavaScript/WebGL 架構，不新增依賴。
- 保留既有存檔格式、經濟規則、最多 8 台無人機、自動模式、電量／充電及離線模擬。
- 工作結果提交與返航完成必須分離；任務結果最多提交一次。
- 路徑失敗不可以直線穿障，也不能阻斷整條派工佇列。
- 動畫交接必須從目前世界座標連續開始；路徑重規劃建立新段並重設該段進度。
- 不宣稱未執行的測試通過；動態瀏覽器驗收與來源斷言需明確區分。

## 分階段任務
- 任務257：盤點呼叫鏈、狀態欄位與失敗路徑，建立基準與可重現測試。
- 任務258：整理任務生命週期、結果一次性提交、取消／失敗／重試與派工邊界。
- 任務259：建立狀態機及位置／路徑控制的單一責任，處理工作高度與尋路失敗。
- 任務260：逐步替換飛行、播種、澆水、採收、返航動畫交接。
- 任務261：完整回歸、桌面／手機驗收、文件與風險收尾。

## 驗收條件
- 規格與所有階段任務文件已建立，階段依賴與驗收標準明確。
- 階段一先取得真實呼叫鏈與測試基準，再開始核心重構。
- 所有階段完成後，播種→澆水、採收→返航及多機接續不瞬移；任務結果不重複；尋路失敗不穿障、不停工。
- JavaScript 語法檢查與 Playwright 桌面／手機回歸有實際結果紀錄。
- 存檔相容、電量、充電、自動模式、離線模擬與 WebGL fallback 維持正常。
