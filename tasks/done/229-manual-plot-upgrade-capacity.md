# 任務229：手動地塊升級與同地塊種植容量

## 需求
為手動地塊設計並加入升級按鈕。每次成功升級，該手動地塊可同時種植的花卉數量上限增加 1；等級不設最高限制。

## 設計原則
- 先檢查目前手動地塊的購買、選取、操作視窗、金幣扣款與存檔流程，再決定升級按鈕的位置及資訊呈現。
- 升級只適用於手動地塊；自動地塊的既有規則與 UI 不變。
- 每次升級增加一個可種植名額，等級／容量不得設固定封頂；需防止非有限數值、負數、重複點擊造成的狀態錯誤。
- 本任務依賴任務228的多株資料模型，容量必須真正限制同一地塊的種植數量，而非只改顯示文字。
- 升級價格曲線（已由使用者授權 Agent 決定）：以目前容量等級 L 計算 `cost(L) = Math.round(40 * L ** 1.4)`。容量 1→2 收 40 金幣、2→3 收 106、3→4 收 186、4→5 收 279、5→6 收 381、10→11 收 1005。價格隨容量平滑遞增，不設固定最高等級；金幣不足時不扣款也不升級。
- 舊存檔的手動地塊預設容量需明確定義為可容納 1 株，升級資訊在存檔／讀檔後保持一致。

## 驗收條件
- 手動地塊操作視窗有清楚的升級入口、目前容量／等級與下一次升級資訊。
- 每次升級成功後容量只增加 1，扣款與狀態更新一致；金幣不足時不扣款、不升級。
- 可連續升級且沒有固定最高等級。
- 容量滿時阻止新增花株並給出明確提示；尚有空位時可繼續種植。
- 升級後重新載入仍保留等級與容量。
- 自動地塊不出現升級按鈕，既有玩法不退化。
- 依已確認的次方價格曲線實作並納入測試。

## 依賴
依賴任務228完成，並需先取得升級價格方案的使用者確認。
