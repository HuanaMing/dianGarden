# 任務 172：縮短 Playwright 瀏覽器驗收流程

## 狀態
**Completed（已完成）**

## 背景
任務 171「清理反覆修改遺留的無用程式碼」已完成，最後一段 Playwright run `39887236576` 成功。本任務已完成基線量測、workflow 修改與完整瀏覽器驗收。

## 目標
在任務 171 全部清理完成並驗收後，調查並降低 GitHub Actions Playwright 瀏覽器驗收流程的執行時間，同時維持驗收可靠性。

## 範圍
- 量測並記錄 workflow 各步驟耗時，找出主要瓶頸。
- 評估使用含瀏覽器系統依賴的官方 Playwright Docker image，是否適合目前 GitHub Actions workflow。
- 視評估結果比較其他低風險方案，例如改善 APT 套件快取；不得假設快取整個系統函式庫目錄是安全或有效的。
- 選擇一項合理方案實作，保持 workflow 簡單、可維護，並避免引入不必要的外部依賴。
- 以獨立提交修改 workflow，執行完整瀏覽器驗收並比較修改前後耗時。

## 不在範圍內
- 任務 171 尚未完成前，不修改 workflow 或開始本任務的實作。
- 不因追求速度而略過 Playwright 測試、資產準備或必要的環境依賴。
- 不更動遊戲程式、遊戲規則、模型外觀、操作流程或存檔格式。

## 驗收條件
1. 任務 171 已完成，且其所有已修改批次均通過驗收。
2. 已記錄目前 workflow 的步驟耗時及瓶頸。
3. 已說明候選方案的相容性、維護成本與預期效益，並選定實作方案。
4. workflow 修改以獨立 commit 提交。
5. 修改後 GitHub Actions 的 Playwright 瀏覽器驗收成功，必要的截圖／驗收產物仍可保存。
6. 比較修改前後耗時；若未改善或發生不穩定，調查原因並修正或還原。

## 執行原則
- 開始前先讀取最新的 `.github/workflows/browser-check.yml` 及近期 Actions 執行紀錄，不依賴舊快照。
- 先量測，再修改；一次只引入一項主要變更。
- 驗收失敗時先調查、修復或還原，不得把失敗方案當作完成。
- 任務完成後更新任務狀態、`state/project.json`、`state/current-task.json` 及工作紀錄。

### 實作與驗收結果
- 方案：移除 Chromium 系統依賴安裝步驟；保留瀏覽器安裝、完整 browser-smoke、截圖上傳及 14 天保存，不引入 Docker 映像或新依賴。
- Workflow commit：`32362119b051d33c4355d0bf39c4a6be2a0ad351`。
- 修改後 run `39889061910` 成功，約 45 秒；所有瀏覽器檢查通過，沒有 browser errors，25 張截圖成功上傳（約 2.9 MB）。
- 修改前正常 run `39887236576` 約 47 秒，常態只快約 2 秒；慢速 run `39885207346` 約 7 分 24 秒，其中 APT 下載花 6 分 38 秒。本次主要收益是避開系統套件鏡像造成的長時間波動，而非大幅降低常態耗時。
- 官方 Playwright container 可預裝瀏覽器與系統依賴，但需同步固定 image 與 npm 套件版本；本次先採用不增加依賴且已完整驗收的最小變更。
- 限制：目前依賴 GitHub `ubuntu-latest` runner 的既有系統函式庫；若未來 runner 或 Chromium 依賴變更導致測試失敗，再評估固定版本的官方 Playwright container。
