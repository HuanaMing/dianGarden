# 任務 183：設定面板版本資訊與立即更新

## 狀態
已完成

## 目標
在設定面板顯示目前版本號、伺服器最新版本號，並提供「立即更新」按鈕。

## 需求
- 設定面板顯示「目前版本號」與「最新版本號」。
- 加入「立即更新」按鈕。
- 按下立即更新時，達到接近 Ctrl+F5 的強制更新效果：重新取得最新 HTML，並為同源 CSS、JavaScript 等靜態資源加入 cache-busting query，避免沿用舊快取。
- 瀏覽器不允許 JavaScript 直接觸發真正的 Ctrl+F5，因此以 no-store 重新抓取頁面、更新同源資源 URL 後重新載入文件來達成等效流程。
- 立即更新前保存目前遊戲狀態；更新失敗時顯示錯誤，不可清除或重置存檔。
- 更新提示中的「重新載入」也應使用同一個強制更新流程，避免兩種更新入口行為不一致。
- 保留既有 version.json 格式及自動檢查行為。

## 驗收條件
- 設定面板中能看見目前版本號、最新版本號及立即更新按鈕。
- 版本檔可用時顯示最新版本；網路失敗時不阻擋遊戲，且 UI 清楚顯示無法取得最新版本。
- 點擊立即更新會以 `cache: no-store` 取得最新 HTML，並對同源 CSS、JavaScript 及圖片資源加入更新查詢參數，再重新解析文件。
- 更新過程不清除遊戲存檔；更新失敗時仍能繼續使用目前遊戲。
- Playwright 自動驗收涵蓋版本資訊 UI 與立即更新的 cache-busting 行為，既有回歸測試通過。
- 更新架構文件、任務狀態與工作歷史。

## 執行結果
- 設定面板新增目前版本號、最新版本號、版本檢查狀態及「立即更新」按鈕。
- Pages 部署流程同時產生 `version.json` 與 `build-version.js`：前者代表伺服器最新版本，後者把目前部署版本嵌入頁面，避免把「最新版本」誤當成「目前正在執行的版本」。
- 立即更新會以 `cache: no-store` 重新取得 HTML，對同源 JavaScript、CSS、圖片、source 等資源加上唯一查詢參數，再替換頁面文件。更新前觸發現有 `pagehide` 存檔處理；失敗時顯示錯誤並保留目前遊戲。
- 更新提示中的「重新載入」也改用相同的強制更新流程。
- GitHub Pages 部署 run 39953488795 成功。
- Playwright 瀏覽器驗收 run 39953660007 成功；設定面板版本資訊、更新提示及立即更新資源 cache-busting 檢查通過，既有遊戲回歸測試通過。
- 驗收過程曾因測試沒有模擬「目前執行舊版本」而未顯示更新提示，已調整測試以攔截 `build-version.js` 模擬舊版，後續驗收成功。
- 瀏覽器不允許網頁 JavaScript 直接呼叫真正的 Ctrl+F5；本實作透過重新取得最新 HTML 與對同源資源加上 cache-busting query，達到接近的強制更新效果。
