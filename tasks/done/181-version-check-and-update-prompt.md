# 任務 181：版本檢查與更新提示

## 狀態
已完成

## 目標
讓已開啟的遊戲能透過同源 `version.json` 偵測新部署，提示玩家在適當時機重新載入；版本檔由 GitHub Actions 在 GitHub Pages 部署時自動產生。

## 版本格式
`YYMMDD,HH`，例如 2026 年 10 月 23 日 22:03 為 `261023,22`。採用 `Asia/Taipei` 時區。由於精度只有小時，同一小時內多次部署會得到相同版本值，這是已知限制。

## 範圍
- 在 Pages 部署工作流程中產生 `src/version.json`，讓它隨 `src/` 一起發布。
- 新增獨立版本檢查腳本，使用 `fetch`、`cache: no-store` 與 cache-busting query 讀取版本。
- 初次取得版本後記錄在專用的本機儲存鍵；偵測版本變化時顯示可延後或重新載入的提示。
- 頁面載入時檢查、遊玩期間每 5 分鐘檢查，頁面重新顯示時再檢查。
- 網路失敗或本機儲存不可用時，不得阻擋遊戲啟動。
- 增加瀏覽器自動驗收，確認版本檔可讀且格式正確。
- 更新必要的工作規範、架構文件、狀態與工作紀錄。

## 驗收條件
- Pages 發布產物根目錄包含格式正確的 `version.json`。
- 版本格式符合 `YYMMDD,HH`，使用台灣時區。
- 版本檢查不阻擋遊戲啟動；失敗時可安靜略過。
- 偵測到新版本時提供重新載入與稍後處理選項。
- 瀏覽器自動驗收通過，且既有遊戲存檔不被清除或改寫。
- 如無法直接驗證線上 Pages 發布結果，須清楚標示限制，不可宣稱已完成線上驗收。

## 執行結果
- 完成 Pages 部署前的版本檔產生步驟，使用 `Asia/Taipei` 並輸出 `YYMMDD,HH` 格式。
- 新增 `src/version-check.js`，在載入、每 5 分鐘及頁面回到前景時以同源、禁用快取的方式檢查版本；更新提示可選擇重新載入或稍後處理。失敗不阻擋遊戲。
- 在 `AGENTS.md` 記錄版本檔應由部署工作流程產生；更新架構文件、瀏覽器驗收與工作紀錄。
- GitHub Pages 部署工作流程 run 39951151594 成功。
- GitHub Actions 瀏覽器驗收 run 39951257421 成功；檢查包含 version.json 同源讀取與格式、版本差異提示及「稍後」按鈕，完整既有 browser-smoke 測試通過，browserErrors 為空。
- 初次新增驗收時曾因測試正規表示式跳脫錯誤而失敗，已修正並由後續 run 重新驗收成功。
- 限制：版本精度只有小時，同一小時內多次部署可能無法被版本值區分；本次未能透過外部瀏覽工具直接讀取線上 version.json，因此只確認 Pages 部署工作流程成功及 CI 驗收通過。
