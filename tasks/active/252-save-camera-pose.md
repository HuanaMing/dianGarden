# 任務252：存檔保存並恢復鏡頭位置

## 需求
遊戲保存紀錄時一併保存目前鏡頭位置與視角；玩家下次登入／載入同一花園時，恢復上次的鏡頭狀態。舊存檔沒有鏡頭紀錄時，使用既有初始鏡頭，不得因此載入失敗。

## 保存資料
依 `src/sky-world.js` 目前相機狀態，規劃保存：
- 相機模式（2D／3D）。
- 3D：`yaw`、`pitch`、`distance`、`targetX`、`targetZ`。
- 2D：`topDownHeight`，以及必要時的視野中心／目標座標。
- 只有有限數值及合法模式可以寫入與還原；載入時需套用既有相機範圍限制。

## 實作方案
- 在 `src/sky-world.js` 提供穩定的相機狀態讀取／還原介面，避免 `src/game.js` 直接依賴相機內部變數。
- `src/game.js` 在一般自動存檔時將相機狀態寫入現有遊戲存檔物件；相機移動／縮放／切換模式後要觸發節流或合適的存檔更新，避免每一影格都寫入 localStorage。
- 載入時先驗證可選的相機欄位，再傳給場景還原；雲端存檔使用同一份遊戲資料時，也需確認新欄位能往返保存。
- 舊存檔缺少相機欄位、欄位無效或來自較舊版本時，沿用初始相機並保留其他進度。
- 不改變現有相機手勢、2D／3D 切換的暫存姿態邏輯。

## 驗收條件
- 平移、旋轉、縮放後保存，重新整理或重新登入後可恢復相同模式與視角。
- 2D 模式的縮放／中心狀態與 3D 模式姿態分別正確保存。
- 舊存檔沒有鏡頭欄位仍能正常載入並使用初始鏡頭。
- 非有限數字、超出限制或未知模式不會破壞整份存檔。
- 本機與雲端存檔流程皆保持相容；更新 `tests/browser-smoke.mjs` 覆蓋舊存檔、有效姿態與無效欄位。

## 依賴與風險
- 主要影響 `src/game.js`、`src/sky-world.js`、`tests/browser-smoke.mjs`，必要時更新架構文件。
- 需避免每幀寫入存檔；鏡頭欄位為可選欄位以維持舊版存檔相容。
