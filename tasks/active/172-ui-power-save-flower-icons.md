# 任務 172：介面整理、省電模式與花卉像素圖

## 目標
改善桌面與手機橫向版的頂部資訊及控制按鈕配置，加入不執行 GPU 繪圖的省電模式與設定介面，並將介面中的花卉 emoji 改為可替換的 32×32 像素圖資產。

## 需求與驗收條件

### A. 頂部資訊卡與按鈕配置
1. 手機橫向與電腦版：最上方花園資訊卡延伸並占滿整個橫幅。
2. 所有平台：將「收合介面」控制移至左側「2D 模式」按鈕上方；將「重製進度」移至「花卉圖鑑」按鈕下方。調整後無人機視窗不可再被這些控制遮擋。
3. 「設定」按鈕放在無人機按鈕旁，以 ⚙️ 表示；尺寸與無人機按鈕相同，並取代目前「進度會自動儲存」提示所在位置。
4. 點擊「設定」開啟設定介面，將「2D 模式」、「省電模式」、「重製進度」與「進度會自動儲存」提示整合至設定介面。
5. 「花卉圖鑑」移至設定按鈕旁，以 📖 表示。
6. 「收合介面」按鈕移至花卉圖鑑按鈕旁；介面展開時顯示 🔼，介面隱藏時顯示 🔽。
7. 「省電模式」按鈕放在「重製進度」按鈕下方；完成設定介面整合後，省電模式切換控制應在設定介面內，避免重複入口。如視覺上需要保留位置，先以共用設定狀態與單一控制為原則。

### B. 省電模式
8. 省電模式必須持續執行遊戲邏輯、時間／天氣更新、花卉成長、無人機工作與自動存檔，但停止 GPU 繪圖工作。
9. 關閉省電模式後恢復正常繪圖，不得重建或重置遊戲進度。
10. 需檢查 WebGL render loop、動畫更新與互動依賴，避免只隱藏 canvas 卻仍持續呼叫 GPU 繪圖。

### C. 花卉像素圖資產
11. 調整程式結構，讓花卉 emoji 的呈現位置可替換為 32×32 像素圖；優先採用共用、可維護的花卉圖示呈現方式，避免各頁面各自硬編碼。
12. 將 `assets/flowers/` 中對應的花卉像素圖，替換目前相對應的花卉 emoji。需檢查主遊戲、花卉圖鑑及其他花種清單／提示等使用位置。
13. 圖像以 32×32 像素呈現，保留像素圖清晰邊緣，避免被平滑放大；若原始資產尺寸或比例不同，先確認實際檔案，不得只假設尺寸。

## 執行順序
1. 先檢查 `AGENTS.md`、現有任務規範、HTML/CSS/JS 架構、目前按鈕與 HUD 的 DOM/CSS、WebGL 繪圖迴圈，以及 `assets/flowers/` 實際資產。
2. 將介面調整與設定入口作為一組規劃，先完成頂部資訊卡及按鈕布局，測試桌面、手機直向與手機橫向。
3. 實作設定面板與控制整合，確認既有 2D、重製進度、自動存檔提示功能未退化。
4. 實作省電模式：分離遊戲更新與繪圖循環；省電時停止 render/GPU 呼叫但保留必要的邏輯更新。
5. 建立共用花卉圖示呈現方式，逐一將 emoji 替換成對應的 `assets/flowers/` 圖像。
6. 每一個可獨立驗收的階段都應獨立提交，先跑靜態檢查，再跑 Playwright 瀏覽器驗收；失敗時先修正，不疊加後續變更。

## 瀏覽器驗收矩陣
- 桌面寬螢幕。
- 手機直向。
- 手機橫向。
- 無人機視窗開啟時確認不被控制按鈕遮擋。
- 設定面板開啟、關閉與各控制功能。
- 省電模式開啟時遊戲邏輯仍更新、GPU 繪圖停止；關閉後正常恢復。
- 主遊戲與花卉圖鑑的花卉圖示皆載入對應資產，沒有破圖，顯示尺寸與像素清晰度符合要求。
- 確認自動存檔、既有遊戲進度與花卉互動未退化。

## 風險與注意事項
- 省電模式不是單純把 canvas 隱藏；需確認 render loop 是否仍呼叫 WebGL。
- 不可因省電而停止遊戲時間、成長、無人機或存檔。
- 重製進度是破壞性操作，需保留明確確認流程。
- 避免只替換主頁 emoji 而漏掉圖鑑、提示或其他花種列表。
- 僅使用 repository 中實際存在的資產與工具，不假設有未配置的建置系統。
