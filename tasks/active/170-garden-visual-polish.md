# 任務 170：花園整體視覺層次升級

## 目標
在十一種花卉專屬模型完成後，改善花園場景的整體閱讀性與自然感，讓花卉、土地、天空及環境光形成一致的視覺層次，同時維持輕量原生 WebGL 架構與既有操作方式。

## 設計原則
- 先建立修改前基準截圖，再以小幅、可回復的局部調整迭代。
- 優先改善既有場景的明暗層次、土地與花卉的對比，以及不同花種混植時的辨識度；不以大幅改色或大量新增幾何取代細節打磨。
- 不更動花種索引、花卉資料、遊戲數值、存檔格式、土地拼接及無人機工作規則。
- 保持桌面與手機操作可用，並注意 WebGL 每影格效能。

## 執行範圍
- 檢查 `src/sky-world.js` 的天空、環境光、土地材質色彩、花卉幾何與深度排序。
- 依任務 169 產生的全花種基準截圖辨識一致性問題。
- 選擇有明確收益且影響範圍小的視覺調整；每輪變更後執行語法及瀏覽器自動驗收。
- 若發現需要大規模重寫渲染流程，先停止並提出方案，不擅自改變架構。

## 驗收條件
- [x] 明確記錄至少一項可由修改前後截圖比較的視覺問題：各地塊土壤紋理原本使用完全相同的固定方向，草地色斑也只比基色更亮。
- [x] 完成局部視覺調整：土壤紋理依地塊座標穩定旋轉，草地色斑加入適度明暗差，減少重複圖案感並增加地表層次。
- [ ] 十一種花卉模型均仍能正常切換與繪製。
- [ ] 桌面、手機首頁及花卉圖鑑瀏覽器驗收通過。
- [ ] 未更動遊戲數值、存檔格式、土地操作或無人機規則。
- [ ] 保存修改後截圖並記錄尚需人工判斷的視覺項目。

## 執行紀錄
2026-10-22 開始執行。預計先使用任務 169 的全花種截圖建立視覺基準，再依實際觀察挑選低風險改善項目，避免在缺乏比較依據時憑空調整整體風格。


## 實作紀錄（2026-10-22）
- `addSoilTexture()`：使用地塊 X/Z 座標計算可重現的旋轉角度，並同步旋轉土壤紋理標記的位置與方向；同一地塊每次重建都維持一致，不引入隨機閃爍。
- `addGrassTexture()`：草地色斑亮度倍率從 `1.025–1.11` 改為 `0.94–1.13`，同時保留原本的確定性位置分布，使斑塊有少量深淺變化。
- 僅調整既有表面顏色與紋理方向，不增加幾何數量、不修改玩法資料或操作規則。
- 已推送程式碼；等待 GitHub Actions 瀏覽器驗收。自動化通過後仍需以截圖人工判斷實際視覺改善程度。
