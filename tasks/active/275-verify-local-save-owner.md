# 任務 275：驗證本機存檔擁有者，避免跨帳號誤上傳

## 需求
1. 目前登入帳號已有雲端存檔時，一律以雲端存檔覆蓋本機存檔；不受本機存檔歸屬或同步中繼資料影響。
2. 目前登入帳號沒有雲端存檔時：
   - 本機同步中繼資料明確記錄其他帳號：建立新的花園，不上傳舊帳號的花園，並同步新花園。
   - 本機同步中繼資料記錄目前帳號，或沒有明確歸屬：沿用本機存檔並同步。
   - 本機沒有存檔：建立新的花園並同步。
3. 訪客及未登入流程不新增額外保護或確認 UI；接受未登入情境原本就存在的進度風險。
4. 現有程式以 `currentSub = claims.sub` 取得登入帳號識別碼，並以 `writeMeta({ userSub: currentSub, ... })` 記錄存檔關聯，因此 `userSub` 是本機同步中繼資料中對應登入帳號的欄位。若 `userSub` 為非空字串且不同於 `currentSub`，就視為明確屬於其他帳號；本機簽章不同只代表內容有變動，不應抹除已記錄的所有權。

## 實作
- `src/cloud-save.js`：雲端存檔存在且內容不同時覆蓋本機；雲端無存檔時，若本機中繼資料明確屬於其他帳號，建立新花園；否則使用本機存檔同步。沒有新增確認 UI。
- `tests/browser-smoke.mjs`：新增任務 275 的靜態來源檢查，確保雲端優先及不同帳號分支存在。
