# 任務 274：重置進度時同步清除本機與雲端存檔

## 需求
使用者在設定中按下「重置進度」並確認後，清除目前帳號的雲端花園與本機花園，避免重新載入或自動同步時又把舊進度還原。

## 現況調查
- \`src/game.js\` 的確認重置流程目前只移除本機遊戲存檔、作物選擇及花卉變種資料，然後重新載入頁面。
- \`src/cloud-save.js\` 管理目前登入帳號、雲端 revision、同步中狀態及本機同步中繼資料；重置流程尚未與雲端清除串接。
- 需要先確認 \`cloudflare/worker.js\` 是否支援安全刪除存檔，以及 D1 的存檔列／revision／session ownership 規則；不可假設現有 PUT/GET API 能直接刪除。

## 實作範圍
- \`src/game.js\`：重置確認後呼叫雲端存檔模組提供的重置流程，成功後才清除本機資料並重新開始。
- \`src/cloud-save.js\`：提供明確的雲端重置介面；確認登入者與目前存檔擁有者一致，停止待執行自動同步，避免舊存檔重新上傳。
- \`cloudflare/worker.js\` 及必要的 Worker smoke tests：若現有 API 不支援刪除，設計經驗證身分、revision／session ownership 保護的刪除操作；不得允許未授權刪除或刪除其他使用者的資料。
- \`tests/browser-smoke.mjs\`、\`tests/cloudflare-worker-smoke.mjs\`：覆蓋本機與雲端重置、失敗處理及回歸案例。

## 行為與失敗處理
1. 未登入時：清除本機花園與相關本機同步中繼資料；不呼叫雲端 API。
2. 已登入且雲端存檔存在時：先要求雲端刪除成功，再清除本機花園並重新載入。
3. 雲端刪除失敗、逾時、登入失效或 revision 衝突時：不得假裝完成；保留本機進度並清楚提示使用者。若已發生部分成功，需設計可恢復／重試流程，避免重載時自動把舊資料上傳回去。
4. 訪客花園與正式帳號花園需維持隔離；不得因重置訪客花園而刪除正式帳號雲端存檔。
5. 清除範圍需包含遊戲存檔、花卉變種、自動作物選擇，以及會導致舊雲端版本再次恢復的同步中繼資料；不得清除登入憑證或無關設定，除非有明確必要及說明。

## 驗收條件
- 未登入重置後，本機遊戲資料消失並建立全新花園，沒有雲端請求。
- 已登入重置後，雲端刪除與本機清除都成功；重新載入、重新登入或觸發自動同步都不會恢復舊花園。
- 模擬 API 失敗、逾時、登入失效、revision conflict 時，不會錯誤顯示成功，也不會無聲丟失唯一副本。
- 訪客模式、其他帳號存檔、長期登入、既有同步衝突保護均通過回歸測試。
- Worker API smoke、瀏覽器 smoke、語法與污染檢查通過。
- 生產 D1 migration 或 Cloudflare Worker 部署如有需要，先完成本機驗證並另行取得明確批准；不得將本機測試通過描述成已部署。

## 狀態
待執行。先檢查 Worker API 與存檔 ownership，再選擇最小且可安全恢復的實作方案。
